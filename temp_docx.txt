10.2. Bảng document_chunks - Dữ liệu nền cho RAG
Lựa chọn HNSW thay vì IVFFlat: HNSW (Hierarchical Navigable Small World) không yêu cầu biết số lượng vector trước khi tạo index, có recall cao hơn IVFFlat, và không cần chạy VACUUM ANALYZE sau mỗi lần insert. Đây là lựa chọn phù hợp hơn cho môi trường production với 50K-500K chunks.
CREATE TABLE document_chunks (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    document_id     UUID NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
    chunk_index     INTEGER NOT NULL,
    content_chunk   TEXT NOT NULL,           -- 256-512 tokens (sliding window)
    embedding       VECTOR(768),             -- bkai vietnamese-bi-encoder output
    token_count     INTEGER
);

-- HNSW index - không cần biết số vector trước, recall cao hơn IVFFlat,
-- không cần VACUUM ANALYZE sau insert, phù hợp production
CREATE INDEX idx_chunks_embedding_hnsw ON document_chunks
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 128);

-- m = 16: số connections mỗi node (trade-off speed/recall)
-- ef_construction = 128: độ chính xác khi build index

11.3. Quy trình ETL (Extract - Transform - Load)
Extract: Tải dữ liệu từ HuggingFace → Chuẩn hóa schema (mapping các trường về schema bảng documents).
Transform: Lọc 2 lĩnh vực trọng tâm (Lao động, Thuế) → Cắt nội dung thành chunks 256-512 tokens với chiến lược sliding window có overlap 50 tokens để giữ ngữ cảnh qua ranh giới chunk.
Embed: Embedding từng chunk bằng bkai-foundation-models/vietnamese-bi-encoder (768 chiều). Batch processing để tối ưu tốc độ.
Load: Lưu metadata vào bảng documents, vector embedding vào document_chunks.embedding. Build HNSW index sau khi insert đủ dữ liệu.
11.4. Hybrid Search với Reciprocal Rank Fusion (RRF)
Hybrid Search kết hợp BM25 (chính xác từ khóa) và Semantic Search (ngữ nghĩa) thông qua thuật toán Reciprocal Rank Fusion (RRF) - không cộng trực tiếp score (vì BM25 và Cosine Similarity có scale hoàn toàn khác nhau), mà kết hợp qua thứ hạng:
# Reciprocal Rank Fusion (RRF) - chuẩn công nghiệp cho Hybrid Search
# Không cộng trực tiếp BM25_score + Cosine_similarity (sai về mặt toán học)
# Thay vào đó, kết hợp qua rank position

def rrf_score(rank: int, k: int = 60) -> float:
    return 1.0 / (k + rank)

def hybrid_rerank(bm25_results: list, semantic_results: list) -> list:
    scores = {}
    for rank, doc_id in enumerate(bm25_results):
        scores[doc_id] = scores.get(doc_id, 0) + rrf_score(rank)
    for rank, doc_id in enumerate(semantic_results):
        scores[doc_id] = scores.get(doc_id, 0) + rrf_score(rank)
    # Sắp xếp theo tổng RRF score giảm dần
    return sorted(scores.keys(), key=lambda x: scores[x], reverse=True)
Lý do dùng RRF: BM25 trả về score dạng TF-IDF (0 đến hàng chục), Cosine Similarity trả về score từ 0.0 đến 1.0 - hai scale hoàn toàn khác nhau, không thể cộng trực tiếp. RRF chỉ dùng rank position (vị trí xếp hạng) nên độc lập với scale của từng phương pháp. k=60 là giá trị mặc định được Cormack et al. (2009) đề xuất và được dùng rộng rãi.
